➕ Agregar un Microservicio Nuevo

Receta paso a paso para que un servicio nuevo encaje en el stack: CRUD ruteado por el gateway + documentado en Swagger, como si siempre hubiera estado.

Ejemplo usado en esta guía: un reportes-service que expone /api/reportes en el puerto 8090 (el siguiente libre). Sustituye reportes / 8090 por los tuyos.

Puertos en uso

PuertoServicio
8080api-gateway
8082–8089pago, clases, evaluaciones, inscripciones, user, auth, certificado, calificaciones
8090+libre → úsalo para el nuevo servicio

1.Clonar un servicio existente como plantilla

Copia la carpeta de un servicio parecido (p. ej. calificaciones_service). Ya trae lo correcto: pom.xml con Spring Boot 4.0.x y springdoc 3.0.3, el Dockerfile multi-stage y las clases de config. Renombra paquete y artefacto.

  • Mantén spring-boot-starter-web (MVC). Elige uno entre webmvc/webflux, no ambos.
  • springdoc-openapi-starter-webmvc-ui debe ser 3.0.3 (la 2.x crashea en Boot 4).
  • spring-boot-starter-oauth2-resource-server solo si el servicio requiere autenticación.

2.Entidad — siempre id autoincremental

@Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
@Schema(accessMode = Schema.AccessMode.READ_ONLY)   // oculta el id del body en Swagger
private Long id;

Nunca un @Id tipo String manual (ese fue el bug de User).

3.Controller — respeta la convención de rutas

El gateway rutea por prefijo de ruta, así que la base del controller debe coincidir con la ruta del paso 8.

@RestController
@RequestMapping("/api/reportes")
@Tag(name = "Reportes")
public class ReporteController {

    @GetMapping("/listar")     // listar todos
    @GetMapping("/{id}")       // obtener uno
    @PostMapping               // crear  (devuelve la entidad guardada)
    @PutMapping("/{id}")       // actualizar
    @DeleteMapping("/{id}")    // eliminar
}
Usa un DTO o la entidad como @RequestBody — nunca Map<String,String> (eso genera el esquema basura additionalProp1/2/3 en Swagger).

4.application.properties — bloque estándar

spring.application.name=reportes-service
server.port=8090
spring.datasource.url=${SPRING_DATASOURCE_URL}
spring.datasource.username=${SPRING_DATASOURCE_USERNAME}
spring.datasource.password=${SPRING_DATASOURCE_PASSWORD}
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver
spring.jpa.hibernate.ddl-auto=update
spring.liquibase.enabled=false
spring.data.rest.detection-strategy=annotated   # oculta los endpoints crudos /reportes
SECRET=esta_es_mi_compleja_clave_secreta_para_jwt_2026_academia_noafer
springdoc.api-docs.path=/v3/api-docs
springdoc.swagger-ui.path=/swagger-ui.html
# solo si vas a sembrar datos:
# spring.sql.init.mode=always
# spring.jpa.defer-datasource-initialization=true

5.SwaggerConfig — servidor relativo (clave para "Try it out")

Copia un SwaggerConfig existente y asegúrate de que tenga:

.addServersItem(new Server().url("/"))   // las llamadas salen por el gateway, no por http://reportes-service:8090

6.SecurityConfig — cópialo tal cual si requiere JWT

Igual que los demás servicios protegidos: permite las rutas de swagger, autentica el resto, decodificador HS256 NimbusJwtDecoder con ${SECRET}.

.authorizeHttpRequests(auth -> auth
    .requestMatchers("/v3/api-docs/**", "/swagger-ui/**", "/swagger-ui.html",
                     "/swagger-resources/**", "/webjars/**").permitAll()
    .anyRequest().authenticated())
.oauth2ResourceServer(oauth2 -> oauth2.jwt(jwt -> {}));

Si el recurso es público, puedes omitir SecurityConfig — pero entonces solo queda protegido por el gateway.

7.docker-compose.yml — agrega el servicio

  reportes-service:
    build: ./reportes_service
    ports: ["8090:8090"]
    environment:
      <<: *common-env
    depends_on:
      mysql:
        condition: service_healthy

Y añade reportes-service al depends_on del api-gateway.

8.Gateway — ruta + entrada en el desplegable de Swagger

En api-gateway/src/main/resources/application.yml. La ruta del predicado debe ser igual a la base del controller, y el RewritePath es obligatorio para los docs:

            - id: reportes-service
              uri: http://reportes-service:8090
              predicates:
                - Path=/api/reportes/**, /v3/api-docs/reportes
              filters:
                - RewritePath=/v3/api-docs/reportes, /v3/api-docs

En la lista springdoc.swagger-ui.urls (el desplegable de servicios):

      - name: 9. Reportes
        url: /v3/api-docs/reportes

9.Construir, levantar y reiniciar el gateway

docker compose up -d --build reportes-service
docker compose restart api-gateway
No te saltes el restart del gateway. Al crear/recrear un servicio, este obtiene una nueva IP; el gateway (Netty) cachea la vieja y responde Connection refused → 500 hasta que lo reinicias.

10.Verificar

GW=http://localhost:8080

# doc agregado (aggregación + servidor relativo OK) -> 200
curl -s -o /dev/null -w "%{http_code}\n" "$GW/v3/api-docs/reportes"

# token y CRUD por el gateway -> 200
TOKEN=$(curl -s -X POST "$GW/api/auth/login" -H "Content-Type: application/json" \
  -d '{"run":"10492048-9","clave":"clave"}' | sed -n 's/.*"token":"\([^"]*\)".*/\1/p')
curl -s -o /dev/null -w "%{http_code}\n" -H "Authorization: Bearer $TOKEN" "$GW/api/reportes/listar"

Luego abre http://localhost:8080/swagger-ui.html → el desplegable muestra 9. Reportes → Authorize con un token → Try it out.
